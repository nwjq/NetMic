# NetMic UI/UX + Tauri 交互规范（合并版）

## 适用场景
- 设计或改造界面布局、视觉风格与交互流程
- 新增配置项、状态指标、日志页面
- 设计/实现 Tauri command、事件流与状态管理
- 调整 UI 与 Rust 的边界、权限与安全策略

## Skill 优先级与边界（避免冲突）
- 在 NetMic 仓库内，只要涉及 UI/UX、IPC 协议、状态机、最小命令集，或“新增配置/指标”的配套步骤，优先使用本 skill。
- `.codex/skills/tauri/SKILL.md` 作为通用补充：需要官方细节（配置字段、插件、分发/签名、平台差异、安全硬化）时再引用它。
- 若两者描述不同：以本 skill 的项目约束为准，再用 tauri skill 补齐实现细节。
- 需要更深入的 Tauri 细节时，优先阅读 `references/tauri-advanced.md`，避免一次性加载过多通用资料。

## 核心目标
- 可理解：用户一眼看懂当前模式与状态
- 可恢复：关键参数有默认值与回退路径
- 可观测：延迟/丢包/缓冲深度等指标持续可见
- 可扩展：新增配置/指标时 UI 与 IPC 成对更新

## 信息架构（MVP）
- 模式切换：Client / Server  
- 配置页：参数 + 默认值 + 回退提示 + 校验  
- 状态页：连接、延迟、丢包、缓冲深度、当前模式  
- 日志页：可导出、可过滤、按级别

## 视觉规范
- 字体：选 1–2 套有辨识度字体，避免系统默认  
- 色彩：中性基调 + 明确状态色（成功/警告/错误/中性）  
- 背景：渐变或细微纹理，避免纯白平铺  
- 层级：关键状态突出，次要配置收敛  
- 组件：表单密度适中，关键按钮位置稳定

## 交互规范
- 参数输入即时校验，错误提示具体到范围/单位  
- 一键恢复默认值；修改后提示“未保存”  
- Streaming/运行中禁用不可变参数  
- 断线与错误必须有清晰提示与下一步建议  
- 开始/停止等关键操作提供明确反馈

## 状态与反馈
- 状态机：Idle → Connecting → Streaming → Error  
- 指标区刷新有节奏感，避免闪烁  
- 页面进入使用轻量过渡

## Tauri 交互原则（UI 相关）
- 架构：Core(Rust) + WebView(UI)，最小权限原则  
- IPC 语义：`command`=请求/响应，`event`=单向通知  
- 最小命令集：`start`/`stop`/`status`（必要时含 `set_config`）  
- 状态管理：全局 `State` 保存连接与配置  
- 指标推送：高频指标用事件流推送 UI，避免轮询  
- 安全：仅开放必要的 `allowlist` 权限

## 需要深入 Tauri 时
- 进程模型、IPC 设计、安全/权限、调试与发布等深入内容，阅读：`references/tauri-advanced.md`

## 新增配置/指标的同步步骤
1) UI 表单/展示与文案  
2) Rust 侧参数校验与默认值  
3) IPC 命令/事件协议  
4) 日志与指标埋点

## 设计输出要求
- 先给信息架构草图，再给视觉与交互细节  
- 说明关键状态与错误场景
