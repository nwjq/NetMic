# Tauri 深度参考（按需阅读）

> 仅在需要深入理解 Tauri 机制、权限、安全或打包发布时阅读。

## 进程模型与安全
- 架构：Core(Rust) + WebView(UI)，遵循最小权限原则
- WebView 不应直接访问系统资源，必须通过 IPC
- 安全策略优先：限制 allowlist、严格 CSP

## IPC 设计要点
- `command`：请求/响应；适合控制流与配置变更
- `event`：单向通知；适合高频指标与状态推送
- 避免高频轮询，指标推送更稳

## 状态管理
- Core 侧用全局 `State` 保存连接与配置
- UI 侧使用统一的状态容器，避免多点来源

## 调试与开发
- 开发调试：使用 DevTools/日志追踪
- 尽量将 UI 与 Core 的日志分层、可过滤

## 分发与签名（需要发布时）
- Windows 需要签名与时间戳配置
- CI/CD 时再引入签名流程，避免干扰开发

## 插件与系统集成（需要原生能力时）
- 优先选择官方/成熟插件
- 自定义插件：明确权限边界与错误回退

## 何时查看官方文档
- 涉及权限、安全、签名、插件开发等高风险主题
- 需要新增平台特性或系统 API 时
