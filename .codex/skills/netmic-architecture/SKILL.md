# NetMic 架构与模块边界

## 适用场景
- 需要定义或调整 Client/Server/共享模块边界
- 需要设计/审查协议与数据流
- 需要评估架构风险与演进路径

## 核心原则
1) 单客户端、单向流（Client → Server）  
2) 数据面 UDP，控制面握手/心跳  
3) 内部标准格式：PCM16 / mono / 48k  
4) 可观测性优先：指标与日志先行  
5) 里程碑递进：先 M0 后 M1/M2/M3

## 工作流程（必须遵循）
1) **读取项目约束**  
   - `MVP.md`  
   - `docs/ROADMAP.md`  
   - `docs/MODULE_OWNERS.md`
2) **绘制数据流**  
   - 采集 → 重采样 → 编码 → UDP → 接收 → 解码 → 缓冲 → 注入
3) **定义接口契约**  
   - 消息结构、参数范围、错误码、状态机
4) **评审风险与观测点**  
   - 丢包/延迟/缓冲深度/重连策略
5) **输出变更**  
   - 需要新增或更新 `docs/INTERFACES.md` 或 `docs/DECISIONS.md`

## 架构评审清单
- 模块责任是否与 `docs/MODULE_OWNERS.md` 一致  
- 协议是否支持单客户端与 BUSY 拒绝  
- 参数是否落在安全范围并有回退  
- 音频链路是否保持内部标准格式  
- 日志与指标是否可定位问题
